# /推敲 — 言葉遣いの総点検（社内薬剤師向けに自然な日本語へ）

対象（引数があればそれ、なければ直近で編集した .html）: $ARGUMENTS

CLAUDE.md「文章・言葉遣いルール」に沿って、対象ページの**本文・見出し**を点検する。GPT等に貼って精査してもらう作業の内製版。

## 手順
0. **先に機械チェックを回す。** 確定済みのNG語はここで全部拾えるので、人が見るのは判断の要る所だけにする。
```bash
cd "D:/☆shared-pages"
node assets/check-wording.js <対象ファイル>     # 省略すると公開ページ全部
```
「要修正」は確定ルール違反なので原則そのまま直す。「確認」は文脈しだいなので目視で判断する。
そのうえで `private/推敲対照集.md` を読み、機械では拾えない基準（文体の線引き・見解ブロックの型・混在チェック）を頭に入れてから1に進む。

1. 対象ファイルを読み、次の観点で問題箇所を洗い出す（CLAUDE.md の7ルール）:
   - ① 硬い・添付文書調 → やわらげる（意味の正確さは崩さない）
   - ② Web制作用語・カタカナ専門語 → 日本語に言い換え
   - ③ 同義語・同じ語の重複 → 省く
   - ④ 事務的・擬人的な言い回し（「案内しています」「〜を参照」）→ 直接的に
   - ⑤ 強すぎる断定・算定に踏み込む表現 → 弱める。**ただし別添3が求める必須の記録要素は残す**
   - ⑥ 用語は厚労省の正式名を優先。現場語と食い違う時は一言添える
   - ⑦ 自社の確立した語り口・編集方針は覆さない
   - さらに CLAUDE.md「内容の混在チェック」4項目（算定要件と社内運用／確認と指導／薬剤師向けと事務向け／テンプレ丸写し感）も併せて点検する

2. **いきなり書き換えず、まず「旧→新」の対照表で提案する**（該当箇所・理由つき）。内容の正確さに関わる変更は特に、勝手に断定せずユーザーの判断を仰ぐ。

3. ユーザーがOKした項目だけ反映する。判断を預けたい境界線（算定に近い記録要素など）は明示して確認する。

4. **今回確定した直しを積み重ねる（毎回やる。ここを飛ばすと同じ推敲を繰り返すことになる）。**
   - 機械で検出できる語（旧→新が一対一で決まるもの）→ `assets/wording-rules.json` に1行足す。**追跡対象なのでもう1台のPCにも届く。**
   - 判断の理由・文脈しだいの基準・見送った理由 → `private/推敲対照集.md` の「9. 個別の直し履歴」に1行足す。
   - 足したら `node assets/check-wording.js` を回し、新ルールが既存ページを誤検出しないか確認する（誤検出するなら `skipSpeech` / `okIfPageHas` / `skipFiles` で絞る）。

5. 反映後、必要なら `/公開` で公開する（このコマンド自体は push しない）。

## やらないこと
- 意味・算定要件の正確さを崩す言い換え。
- 当社の語り口を無視した全面書き換え（外部提案でも意図を優先）。
- 個人情報の追加。draft/ の非公開ルール違反。
