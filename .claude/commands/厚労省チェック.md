# /厚労省チェック — 厚労省の新着を拾う

## 0. USB が挿さっているか確かめる（定期実行のとき）

このリポジトリは USB の上にあり、定期実行は2台のPCの両方に登録してある。USB が挿さっていないPCでは何もせずに終える。

```bash
ls "D:/☆shared-pages/tools-internal/mhlw-watch.js" 2>/dev/null || ls "E:/☆shared-pages/tools-internal/mhlw-watch.js" 2>/dev/null || echo "USBなし"
```

「USBなし」なら「USB が挿さっていないので今回は見送り」と1行だけ報告して終える（ほかのツールを呼ばない）。E: で見つかったら、以下の `D:` を `E:` に読み替える。

USB が見つかったら、新着を見る前に private/ と draft/ の控えを取る（USB が壊れたときの備え。コピー先はこのPCのデスクトップ「サイトの控え（USB）」）。定期実行の指示文に「書き込みは private/厚労省チェック/ の中だけ」とあっても、このコピーは本人が決めた例外として行ってよい。失敗しても止めずに先へ進み、最後の報告に1行添える。

```bash
node tools-internal/backup-private.js
```

## 1. 新着を機械で拾う（Claude を使わないので何度回してもよい）

```bash
cd "D:/☆shared-pages"
node tools-internal/mhlw-watch.js
```

見るページと関係ありとみなす語は `tools-internal/mhlw-watch.json`。ページを足したいと言われたらここに1行足す。
出力の最後に「復旧待ち」（落ちているサイトが戻ったか。mhlw-watch.json の waitFor）が出る。**★ 復旧した** があれば最初に報告する。
新しい行が0件なら「新着なし」と1行で報告して終わる（ここで止めれば使用量はほぼかからない）。

## 2. ★（関係あり）の行だけ中身を見る

- 会議のページ（`newpage_…`）は WebFetch で開き、**議題と資料名**だけを読む。資料のPDFは開かない（本人が必要と言ったときだけ）。
- 通知・事務連絡のPDFは題名だけで判断する。調剤・薬局に直接関係するものだけ、`.claude/skills/read-doc` で中を読んでよい。
- ★の付かない行（・）は読まない。件数だけ数える。

## 3. 報告とネタ帳

`private/厚労省チェック/YYYY-MM-DD.md` に次の形で残し、本人には要点だけを出す。

```
# 厚労省チェック YYYY-MM-DD
## 調剤・薬局に直接関係する（すぐ見る）
- 【会議名 第○回 M/D】議題：…（URL）
  → サイトへの影響：○○のページ（加算まとめ/…）に関係しそう／新しいページの候補
## 動きとして押さえておく（OTC類似薬・介護報酬改定など）
- …
## 関係なさそう（件数のみ）
- ○件
```

- **サイトへの影響は、既存ページを本文の語で探してから書く**（推測で書かない）。探すときは次の形にする。`grep ... $(git ls-files)` は使わない（git がファイル名の日本語をエスケープして出すので grep がファイルを開けず、0件に見える。2026-10-19 にこれで影響ページを見落とした）。
  ```bash
  git -c core.quotepath=false grep -l "居宅療養管理指導" -- "*.html" | grep -v "^draft/"
  ```
- ★の判定は行の文で行う。審議会のページで「資料」「開催案内」だけのリンクは mhlw-watch.js がリンク先の題名を足してから判定するので、出力の行頭に会議名が付く。それでも★が付かない行に「介護給付費分科会」「中医協」の回があれば、念のため会議ページを開く。
- 未確定の議論（中医協の論点・検討会の案）は「議論中」と明記する。速報ページを作るかどうかは本人が決める（未確定制度の速報ページは事実だけを書く方針）。
- 要約は会議の資料に書いてあることだけにする。報道やWeb検索の要約で補わない。
