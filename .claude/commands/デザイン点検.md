# /デザイン点検 — デザインルール準拠チェック

対象: $ARGUMENTS
（引数があればそれ。「全部」ならトップ階層の全 .html。無ければ直近で編集した .html。`draft/` は非公開なので明示された時だけ対象にする）

CLAUDE.md「デザインルール（厳守・2026-06-02 刷新版）」に照らして点検する。判断に迷ったら刷新済みリファレンス実物と見比べる:
`選定療養_概要2026.html` / `調剤時残薬調整加算.html` / `薬学的有害事象等防止加算.html` / `在宅薬学総合体制加算2026.html`（`調剤報酬QA.html` は作成中＝対象外）

## まず機械で測る（目視の前に）

文字色の薄さは**目で見て判断しない**。薄いグレーは「補助テキストらしく」見えてしまい、実際には読めない濃さでも気づけない（2026-09-10 に22ページがこれで見つかった）。

```bash
node assets/check-contrast.js          # 公開ページ全部
node assets/check-contrast.js 加算まとめ/調剤管理料_2026改定.html   # ファイル指定
node assets/check-contrast.js --ng     # 「要修正」だけ
```

- **「要修正」は公開前に0件にする。** 補助テキストは `--txt-3`（#5e6470）。`--border-dk`（#9ca3af）と `#888`〜`#bbb` は文字色に使わない
- 「確認」は矢印・「・」・チェック枠など**読まなくても意味が通る記号**かもしれないもの。記号なら薄くてよいので、そのままでよい
- 淡い背景に色文字を載せるなら「図解の淡色パレット」の背景・文字のセットを使う（そのまま4.5以上になる）

CSS を読んで判定するので、**実際に効いている色**（親から受け継いだ色・後から上書きされる色・重なった背景）は分からない。大きな改修のあとや全体点検のときは、ブラウザで描画してから測るほうも通す：`tools-internal/contrast-scan-browser.js`（使い方はファイル冒頭）。この2枚は取りこぼす場所が違うので、両方通すと漏れがない。

## チェック項目
**配色（最重要）**
- [ ] `node assets/check-contrast.js --ng` が0件
- [ ] 赤（`--red` / `#cc0000` 等）を**使っていない**（定義はOK、使用はNG）
- [ ] 基本は青＋黄マーカー＋補助グレーの3役で構成。むやみに色を増やしていない
- [ ] アンバー（`--amber`系）を安易に使っていない。**最終手段**の条件（並列2系統以上の対比が必要 等）を満たす時だけ。単発の注意喚起にアンバーはNG
- [ ] **NG・不可をアンバーで表していない** → 中立グレー＋「×」印になっているか
- [ ] カテゴリ色を使う場合、番号・ラベル・罫線で足りないやむを得ない例外に限られているか
- [ ] 補助グレーが薄すぎない（`#999`以下は「・」等の弱い記号だけ）
- [ ] `assets/` の共通パーツ（site-header.js / site-search.js / site-recents.js / page-toc.js）を直したら、色は全ページに効く。ここも測る

**旧ルールの残骸**
- [ ] 廃止変数（`--blue-light` / `--sub` / `--bg:#f5f7fa` 等）が残っていない
- [ ] `:root` が現行テンプレの変数構成になっている

**構造・見出し**
- [ ] フォントが Noto Sans JP。`.page`(max-width:900px)＋`.card` の縦積み
- [ ] H1=装飾なし＋サブ説明 / H2=青縦棒＋下線 / H3=青四角（`.sub-title`）
- [ ] 箇条書きの「・」はグレー（H3の青四角と区別）
- [ ] 番号バッジ: 順序=青地・白文字の角丸四角 / ケース=黒丸◯（`.pat-num`）。役割が衝突していない

**共通パーツ・仕上げ**
- [ ] `<body>`直後に `site-header.js`。**手動の「← トップに戻る」ボタンを置いていない**（二重防止）
- [ ] `</body>`直前に GoatCounter タグ
- [ ] `@media (max-width:640px)` と `@media print` がある

## 手順
1. まず `node assets/check-contrast.js` を走らせる。そのうえで対象を読み、上のチェックに沿って**違反箇所を一覧化**する（箇所／違反ルール／修正案の対照表）。問題なし項目は「OK」で簡潔に。
2. **いきなり直さず、まず一覧を提示**。修正するかはユーザーの判断を仰ぐ。
3. OKした項目だけ反映。反映後、必要なら `/公開` で公開する（このコマンド自体は push しない）。
