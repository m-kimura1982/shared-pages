# /加算ページ — 加算・管理料ページの第1段階生成（原文ベース）

対象の加算・管理料名: $ARGUMENTS
（例：`/加算ページ 乳幼児服薬指導加算`。区分番号が分かればそれも添えてよい）

ページ作成は2段階で行う。このコマンドは**第1段階＝原文に忠実な下書き**を作るところまで。
かみ砕き・現場の色（誤解しやすい点・社内運用）は**第2段階＝木村さんとの対話**で足す。
第1段階では上手に書こうとせず、原文の語彙に寄せて正確に組むことを優先する。

## ソース（この6点のみ。外部知識・Web検索で要件を補完しない）
1. `改定資料/別表第三_調剤報酬点数表2026.html` — 告示。点数・注・算定単位
2. `改定資料/別添3_調剤報酬点数表に関する事項2026.html` — 通知。留意事項 (1)(2)…
3. `改定資料/別表Ⅰ_調剤報酬明細書摘要欄記載事項2026.html` — 摘要欄のレセプト表示文言
4. `改定資料/特掲診療料_施設基準届出_調剤関係2026.html` — 施設基準・届出・様式・経過措置
5. `改定資料/疑義解釈まとめ2026.html` — 2026改定の疑義解釈（gigi-list 用の sec-id 確認）
6. `ナレッジ/調剤報酬QA.html` — 社内Q&A（qa-list 用の c-id 確認）

薬歴マニュアル（yakureki/）からは**リンク先の確認と、この加算固有の記載事項の事実だけ**拾う。
文章は流用しない（読者と目的が違うページなので、文体が混ざる）。

## 手順
1. **文体と構成を実物に合わせる。** 書き始める前に必ず読む:
   - `加算まとめ/外来服薬支援料1.html`（実物リファレンス。カードの並び・見出し・文の硬さの見本）
   - `private/推敲対照集.md`（用語・表記の確定基準）
   - `draft/加算まとめ_テンプレート.html` の冒頭コメント（構成の並び・要件/注意の線引き・原文無装飾などのルール一式）

2. **正本から該当区分を抽出する。** 別表第三の区分・注／別添3の該当項／別表Ⅰの表示文言／
   特掲届出の該当箇所。アンカー id（`ku〇〇` / `kub-〇〇`）もこの時に控える。
   見つからない要素（摘要欄なし・施設基準なし等）は「ない」と確定させてから進む。
   - **併算定不可・排他の根拠は、相手側の加算の注に書かれていることがある。** 類似・排他の
     相手がありそうな加算は、相手側の注も必ず確認する（例：小児特定加算の注11に
     「この場合において、注10（乳幼児服薬指導加算）に規定する加算は算定できない」）。
   - **薬歴記載事項の根拠は 別添3 薬学管理料 通則(4)(5)**（アンカー例 `kub-10-3-ts`）。
     令和6改定で個別の薬歴記載事項が削られた加算（乳幼児服薬指導加算など）も、通則(5)
     「薬学管理料やその加算を算定する場合には、その根拠及び指導内容等について簡潔に記載する」
     により薬歴記載は必要。**「記載不要」と書かない**（個別指導では算定した加算の記載を求められる）。
     手帳記載が算定要件の加算（乳幼児・小児特定・吸入薬指導 等）は、手帳（算定要件）と
     薬歴（通則(5)）で内容が違うので分けて示す。
   - **加算ページに書くのは記載項目まで。薬歴の記載例（実際の文章）は書かない**（手順7へ回す）。

3. **テンプレを複製して生成する。** `加算まとめ/〈加算名〉.html` に直接作る（../ パスで書く。
   ルート直下や draft/ に置かない）。**公開までは git に add しない**（未コミット＝サーバーに存在しない＝非公開）。
   - 固定カード（概要・算定要件・算定上の注意・薬歴・摘要欄・原文・原文参照リンク）を原文から組む。
     概要は原文(1)の語彙で1〜2文。注・区分が複数あれば概要で全パターンに触れる
   - 原文折りたたみは一字一句転記・**無装飾**。出典行を必ず付ける
   - 任意カードは該当があるときだけ。類似比較・算定事例などの「色」が要るカードは、
     骨組みと判断軸だけ置いて第2段階へ回してよい
   - 数値（点数・回数・期間）は転記のたびに原文と突き合わせる

4. **疑義解釈・社内Q&Aを接続する。** `node assets/build-gigi-list.js` を実行し、
   末尾の「ブロック未設置」一覧を見て sec-/c- のマーカーを置く。該当がなければブロックごと削除。
   **過去改定の疑義解釈は要旨を書かない**。`../ツール/gigi-search.html?q=〈検索語〉` のリンク1本にする。
   検索して件数だけ確認し、現行制度に関わる重要な問答があれば報告する（載せるかは木村さんの判断。
   旧制度時代＝要件・回数が今と違う頃の問答は現行に当てはまらないので載せない）。

5. **/推敲 のセルフチェックを通す。** 7ルール＋内容の混在チェックを自分で当ててから提出する
   （対照表の提示は不要。直せるものは直してよい。ただし算定可否に関わる言い換えは手を付けず報告）。
   最後に機械チェックを回し、**「要修正」を0件にしてから提出する**。
```bash
node assets/check-wording.js 加算まとめ/〈ファイル名〉.html
```

6. **薬歴の記載例は別ファイルにたたき台を出す。** 原文を読んだこの段階で作るのが一番安いが、
   加算ページのHTMLには入れない（記載例の正本は薬歴マニュアル）。
   `draft/薬歴記載例_未精査/〈加算名〉.md` に次の形で置く:
   - 記載項目（別添3の該当項を根拠として明記。通知に個別の定めがなければ通則(5)）
   - 記載例のたたき台。注・区分で書き分けが要るなら（注１）（注２）と分岐で並べる
   - 判断に迷った点・確認してほしい点（確認と指導の書き分け、対象の絞り方 など）
   - 想定する掲載先（`yakureki/加算別記載一覧.html#〈アンカー〉` か、個別ページ新設か）
   加算ページ側は記載項目のカード＋薬歴マニュアルへのリンク1行で完成とする。
   **精査前に薬歴マニュアルへ書き込まない**（掲載は木村さんの確認後）。

7. **「要肉付け」一覧を添えて提出する。** 第2段階で木村さんの判断・材料が要る箇所を明示する:
   - 概要のかみ砕き／誤解しやすい点／類似比較の判断ポイント
   - 社内運用・レセコンの注意
   - 手順6で出した薬歴記載例のたたき台（要精査）
   - 算定可否の解釈が割れうる論点（あれば）

## 提出前の確認（実際に外した点。作りながら追記していく）

テンプレの冒頭コメントに書いてあるのに毎回埋もれるので、独立させた。提出前に1つずつ当てる。
新しい失敗が出たらここに1行足す。

- **リード文（lead-note）は判断の分かれ目があるときだけ置く。** 区分の説明を文章で繰り返したものは
  概要ではない。区分が表にあるなら、リード文を置かずサブタイトルから表に入る
- **「区分 × 属性」が2つ以上並んだら、箇条書きにせず表にする。** イに2場面・ロに3場面あるなら、
  その5つを表の行にする。「イに当たる場面」のような見出しで箇条書きを積むのは不可
- **表には要件そのものを入れ、表の外で説明し直さない。** 表に入れたことを箇条書きで繰り返すと
  同じ内容が2回出る。表の下に置くのは全区分に共通する事項（「共通要件」）だけ
- **表の列見出しは既存ページで使っている言葉から選ぶ。** 区分ごとの要件を並べる列は素直に
  「算定要件」。「告示の定め」「その区分になる場合」のような造語・回りくどい言い方をしない
- **表が平坦に見えたら、行ごとに決め手を1か所だけ太字にする。** 太字を1行に散らすと元に戻る。
  区分が2群以上あるなら、区分セルを rowspan でまとめ、群の境に濃い罫線を入れて羅列に見せない
  （実物：加算まとめ/特定薬剤管理指導加算3.html）
- **サブタイトルはページの骨格と合わせる。** 通知(1)の抽象的な言い回しをそのまま置かない。
  本文で否定・限定している条件をサブタイトルに書かない（再算定があるのに「最初の1回」と書く等）
- **黄マーカーは読ませたい箇所に引く。** 数は内容による（上限は決めない）。引かないのは、加算の
  前提として当たり前のこと（「重点的な指導が必要と認めて」等）と、単独で引くと誤解を生む数量条件
  （「最初に処方された１回に限り」＝初回しか算定できないと読める）
- **見出しと本文の日本語を口に出して確かめる。** 「〜に当たる場面」のように普段使わない言い回しに
  なっていないか（推敲対照集 8「同僚に口頭で説明するときにこの言葉を使うか」）

## やらないこと
- 外部知識・Web検索・記憶で算定要件を補完しない（ソース6点にない要件は書かない）
- 算定可否の断定を勝手に足さない（「算定できる／できない」の言い切りは原文・疑義解釈に根拠がある場合だけ）
- 原文への装飾（黄マーカー・太字）。線を引きたくなったら本文カードに書く
- 略称の発明（「料１」等）。正式名で書く
- 公開作業（PAGES登録・ハブカード・index/updates 反映・push は `/公開` で別途）
