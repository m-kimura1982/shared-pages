# /公開 — ページ公開の定型手順（反映漏れ・バッジ再生成忘れを構造的に防ぐ）

対象ページ（引数があればそれ、なければ直近で編集した .html）: $ARGUMENTS

以下を**順番どおり**に実行する。各ステップは飛ばさない。

## 0. 前提の確認（ユーザーに1回だけ聞く。自明なら聞かない）
- これは「新規ページ」か「既存ページの更新」か。
- NEWバッジ（🆕）を付けるか（新規、または大きな更新のとき付ける。付ける場合は公開日から約1週間後の日付 `YYYY-MM-DD` を `newUntil` に使う）。
- ツール系など「更新情報に載せなくてよい」ものか（その場合ステップ2の一部を省く）。

## 1. draft/ の非公開ルール違反がないか確認
- 対象が `draft/` 配下なら**公開してはいけない**。index / updates / kaitei2026 から `draft/` への導線も作らない。該当したら中止してユーザーに確認。

## 1.5 site-header.js の PAGES 登録確認（検索・パンくず漏れ防止）
- 新規ページなら `assets/site-header.js` の PAGES に1行登録する（category＋title）。**未登録のページはサイト内検索・パンくずに出ない。**
- ついでに全体の登録漏れ・死にエントリを照合する（bash）:
```bash
cd "D:/☆shared-pages"
for f in *.html; do grep -qF "'$f'" assets/site-header.js || echo "PAGES未登録: $f"; done
```
- ページを削除・draft退避した場合は、PAGES から該当エントリを削除する（残すと検索結果が404になる）。
- **新規ページはカテゴリのハブにもカードを追加する**（加算まとめ.html／checklists.html／tools.html／knowledge.html 等。`data-keywords` にかな読みも入れる）。PAGES登録だけではハブの一覧に出ない（2026-07-24 の外来服薬支援料１公開時に発覚した抜け）。

## 1.7 疑義解釈・社内Q&A一覧の再生成（正本を触ったときだけ）
`改定資料/疑義解釈まとめ2026.html` または `ナレッジ/調剤報酬QA.html` を編集したなら、各ページの一覧ブロックを作り直す。
```bash
cd "D:/☆shared-pages"
node assets/build-gigi-list.js
```
- 差分が出たページも忘れずコミット対象に含める（一覧が古いまま公開されるのを防ぐ）。
- 実行末尾に出る「ブロック未設置」の一覧を見て、新規ページに繋げるものがないか確認する。
- 正本を触っていないなら実行不要（`--check` で差分ゼロを確認してもよい）。

## 2. 3か所へ反映（`feedback-updates-3places` のルール。抜けたらユーザーが手作業で直す羽目になる）
掲載不要な更新でない限り、次の3ファイルすべてを見て反映する:
1. **index.html** —「最近の更新」リストは**5件固定**。新項目を先頭に足し、いちばん古い1件を削って常に5件に保つ。
2. **updates.html** — 更新履歴の**最上位**に日付順で1件追加（件数制限なし）。
3. **kaitei2026.html** — 該当する改定資料カードに `data-new-until="YYYY-MM-DD"`（公開日＋約1週間）を付ける。期限切れの他カードから古い `data-new-until` を消す。
   ※ このカード属性は表示バッジには使われない（バッジ判定は page-meta の値が正）。カードの位置づけ整理のためだけに付ける。

反映した更新文（日本語の文言）は**コミット前にユーザーへ提示して確認をとる**（調剤報酬は内容ミスが実害になるため）。

## 3. NEWバッジを付ける場合だけ: page-meta に newUntil を手書き
`assets/page-meta.json` と `assets/page-meta.js` の**両方**の対象ファイルのエントリに `"newUntil": "YYYY-MM-DD"` を追加する。
（`lastUpdated` は次のステップのスクリプトが git から自動で入れるので手書きしない。）

## 4. ページを先にコミット（※ここが重要な順番）
`build-page-meta.js` は **git のコミット日**から `lastUpdated` を読む。先にページをコミットしないと更新日が今日にならない。
```bash
cd "D:/☆shared-pages"
git add <対象ページ> index.html updates.html kaitei2026.html assets/page-meta.json assets/page-meta.js
git commit -m "<内容がわかる日本語メッセージ>"
```

## 5. 更新バッジを再生成 → もう一度コミット
```bash
cd "D:/☆shared-pages"
node assets/build-page-meta.js
git add assets/page-meta.json assets/page-meta.js
git commit -m "page-meta 再生成"
```
※ スクリプトは手書きの `newUntil` を保持したまま `lastUpdated` を各ページの最新コミット日に更新する。差分が出なければ（既に最新なら）このコミットは省いてよい。

## 6. push して報告
```bash
cd "D:/☆shared-pages"
git push
```
push後は必ずユーザーに「**3点反映済み・更新バッジ再生成済み。公開したのでチェックしてください**」と伝え、確認先URL（https://m-kimura1982.github.io/shared-pages/ ）を添える。掲載不要な更新だった場合はその旨も明記する。

## やらないこと
- `.claude/settings.local.json` / `launch.json` はコミットしない。
- `draft/` 配下や個人情報は公開しない。
- 内容の正誤は最終的に人が確認する前提。勝手に断定・全自動で押し切らない。
