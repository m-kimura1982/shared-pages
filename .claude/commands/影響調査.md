# /影響調査 — 変更影響調査係を呼ぶ

変わった内容: $ARGUMENTS
（例：`/影響調査 調剤時残薬調整加算の算定上限が3月に1回に`。引数がなければ、この会話で直した制度の中身を1行にまとめて使う）

1. **impact-checker** エージェントを起動する（バックグラウンドで）。
   依頼文は「変更：〈何が・どう変わったか〉。直したページ：〈パス。あれば〉」だけにする。どこが怪しいかは書かない（探す範囲を狭めないため）。
2. 報告が届いたら、**「要修正」を自分でもそのページで確かめてから**本人に出す。照合係と同じく、報告は判断材料。
3. 出し方：
   - 要修正 → 「以前の記載／直した後」の対で示す
   - 確認 → 直すかどうかを本人に聞く。チェックリストは「刷り直しの連絡が要るか」も添える
   - サイト外の資料（社内会議のスライドなど）→ その場で直さず、`private/タスク.md` の該当する行に「〈どのスライド〉を直す」と書き足す
   - 自動生成 → `node assets/build-genbun.js` / `node assets/build-gigi-list.js` を回せば直るので、まとめて1行
4. 直すのは本人の了承のあと。直したら /公開 の流れに乗せる。

**いつ呼ぶか**（本人に聞かずに呼んでよい）：/照合 で「不一致」が出て直すとき／厚労省チェックで通知・疑義解釈が出て既存ページに響きそうなとき／点数・要件・期限・名称を変える改修をしたとき。言葉遣いだけの修正では呼ばない。
