# /部署 — 部署の一覧

次の表をそのまま本人に見せる（説明を足さない）。そのあと「どれを動かしますか？」と1行だけ聞く。$ARGUMENTS にページ名があれば、そのページに使える部署を勧める。

**この表が部署の名簿の正本。** 部署を足す・名前を変えるときはこの表を直し、`node tools-internal/build-busho.js` で一覧ページ（private/部署一覧.html）を作り直す。

**新しいページ**：書く → `/通読`・`/照合`（並行。薬の中身を書いたページは `/添文照合` も） → `/推敲` → `/公開`
**制度の中身を変える改修**：直す → `/照合`（薬の中身を変えたときは `/添文照合` も） → `/影響調査` → 響く所を直す → `/公開`
**言葉・見た目だけの修正**：直す（自動検品が走る） → `/公開`

**取りまとめ（司令塔）**：部署を動かすのは、本人と話している会話（司令塔）。係の報告は届くたびに本人へ流さず、全員の報告がそろってから司令塔が指摘を確かめ、決められるものは直したうえで「直したこと（短く）」と「判断が要ること（3つまで）」の1回にまとめて出す。照合を広げる追加の依頼は、本人が頼んだときか誤りの影響が大きいときだけ。
**係への頼み方**：対象ページと、設計メモなど決定済みの方針のパスを渡す。こちらの狙いや気になっている点は書かない（先入観を渡さない）。
**係の報告の分け方**：「新しい指摘」と「決定済みだが気になる点」を分けて書かせる。決定済みのことをもう一度踏むのは、正しい資料を作る過程として残す。

**モデルの使い分け**：別の会話として動く係（読者係・影響調査係＝Sonnet、照合係＝Opus）だけ軽いモデルに振る。定期実行の厚労省チェックは Opus のまま（新着なしの日は数手で終わり、差が小さい）。会話の中で動く係（公開・タスク・期限点検など）は会話と同じモデルのまま（長い会話の途中で切り替えると会話全体を読み直すことになり、かえって高くつくため）。
