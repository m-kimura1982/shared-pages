# /部署 — 部署の一覧

次の表をそのまま本人に見せる（説明を足さない）。そのあと「どれを動かしますか？」と1行だけ聞く。$ARGUMENTS にページ名があれば、そのページに使える部署を勧める。

**この表が部署の名簿の正本。** 部署を足す・名前を変えるときはこの表を直し、`node tools-internal/build-busho.js` で一覧ページ（private/部署一覧.html）を作り直す。

**新しいページ**：書く → `/通読`・`/照合`（並行。薬の中身を書いたページは `/添文照合` も） → `/推敲` → `/公開`
**制度の中身を変える改修**：直す → `/照合`（直した所と、同じページで同じことを書いている所だけ。ページ全体の照合は新規ページのとき。薬の中身を変えたときは `/添文照合` も） → 照合の報告に「公開ページの不一致：あり」があれば、直したあと `/影響調査` → 響く所を直す → `/公開`
**言葉・見た目だけの修正**：直す（自動検品が走る） → `/公開`

**取りまとめ（司令塔）**：部署を動かすのは、本人と話している会話（司令塔）。係の報告は届くたびに本人へ流さず、全員の報告がそろってから司令塔が指摘を確かめ、決められるものは直したうえで「直したこと（短く）」と「判断が要ること（3つまで）」の1回にまとめて出す。照合を広げる追加の依頼は、本人が頼んだときか誤りの影響が大きいときだけ。
**影響調査の結果の扱い**（本人の確認を増やさないため）：同じ数字・名称が古いまま残っている所は司令塔が直して「直したこと」に1行で書く。チェックリストの刷り直しが要るもの・判断が分かれるものだけ本人に聞く（「判断が要ること」の3つの中に入れる）。サイト外の資料（会議のスライド等）はタスク帳へ。

**係への頼み方は、下の「依頼文の型」を写して埋める。** 型にない欄は書き足さない。型は各係が「依頼に必ず入れてほしい」と挙げたものから作った（2026-11-03）。
- 読む・見る役（読者係・聞き手役・想定質問係・反対意見係）には、狙い・直したい案・心配な点・「〜になりそうか」を書かない（先入観を渡さない）
- 照合する役（照合係・添文照合係・影響調査係）には、照らす観点と場所は書いてよい。望む結論や自分の読み方は書かない（読み方を確かめたいときは「文面から言えること／言えないこと」で頼む）

### 依頼文の型

読者係・聞き手役・想定質問係
```
対象：<パス。スライドは画像を順番どおりに>
読者：<立場を具体的に。例：事務・経験3年・成分名に弱い／算定の基本は知っている薬剤師>
前提：<見る環境。例：事前録画・発表者は画面を指して口で補う／ページをスマホで読む>
原稿：<スライドの読み上げ原稿のパス。なければ「なし」。ページのときは省く>
決定済み：<設計メモ等のパス。なければ省く>
```

照合係・添文照合係
```
対象：<パス>
正本：<既定と違うときだけ。添文の抽出テキストを渡すならそのパスと取得日>
観点：<照らしてほしい項目があれば。例：間質性肺炎の注意の有無／直した所はこの3か所>
決定済み：<設計メモ等のパス。把握済み・保留の点もここに>
```

影響調査係
```
変更：<照合係の報告の不一致の項目をそのまま貼る。または何が・どう変わったか1行>
直したページ：<パス>
```

デザイン係
```
対象：<画像のパス（順番どおり）>
前提：<録画か投影か・読み上げるか口で補うか>
原稿：<パス。なければ「なし」>
決定済み：<決めごと以外に、この資料で本人と決めた型>
```

反対意見係
```
案：<1〜3行。または設計メモのパス>
```

**部署の声を吸い上げる**：各係は報告の最後に、困ったときだけ「頼まれ方：…」を1行書く。司令塔は届いたら `private/部署の声.md` に日付・係・その1行を足す（本人には出さない）。月1回の /期限点検 のついでに司令塔がまとめ、型や定義を直したほうがよいものだけを本人に出す。
**係の報告の分け方**：「新しい指摘」と「決定済みだが気になる点」を分けて書かせる。決定済みのことをもう一度踏むのは、正しい資料を作る過程として残す。

**モデルの使い分け**：別の会話として動く係（読者係・影響調査係・想定質問係＝Sonnet、照合係・反対意見係＝Opus）だけ軽いモデルに振る。定期実行の厚労省チェックは Opus のまま（新着なしの日は数手で終わり、差が小さい）。会話の中で動く係（公開・タスク・期限点検など）は会話と同じモデルのまま（長い会話の途中で切り替えると会話全体を読み直すことになり、かえって高くつくため）。
