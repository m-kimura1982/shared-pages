# 原文・疑義解釈・社内Q&A の自動生成

> CLAUDE.md から分けた細則（2026-11-17。文面はそのまま）。**加算ページに原文や疑義解釈の一覧を置くとき・正本を直すとき・疑義解釈や社内Q&A を追記したときに読む。**

### 原文（告示・通知・施設基準）も各ページに自動生成する（2026-08-31）

**加算ページには原文を書き写さない。** 正本は `改定資料/` の3枚（別表第三＝告示／別添3＝通知／特掲診療料＝施設基準）で、各ページにはマーカーを置いて `assets/build-genbun.js` で生成する。手で転記すると誤字が入るうえ、正本を直したときに片方が古くなる。

**正本の3枚は厚労省PDFの文面どおりにする。要約も省略もしない**（2026-09-02に確定）。区分番号・法律名・かっこ書きを省くのは**解説ページの本文だけ**で、読者が原文のどこかを確認しに行かないから省いてよい、という理屈。正本はその確認先なので省いてはいけない。原本PDFは `files/２０２６改定原本_9.2追加分/` にある（**gitに入れていない**。容量が大きく厚労省から取り直せるため。別PCで照合するときは厚労省から落とし直す）。

**正本を直したら、原本PDFと機械照合して差分ゼロを確認する。** 2026-09-02の照合で、別添3に12字ぴったりの脱落が9か所（「・残薬が生じて」で切れる等）、別表第三の注に18か所の欠落が見つかった。どちらも初期作成時の取り込み由来で、目視では見つからない。照合スクリプトは `private/` にある（`restore-chu.js` は注を原本の文面に戻す）。

```bash
node assets/build-genbun.js          # 生成して書き込む
node assets/build-genbun.js --check  # 差分の確認のみ
```

```html
<!-- 原文（自動生成：node assets/build-genbun.js。マーカーの間は上書きされる） -->
<!-- genbun betten3="kub-10-3-12" hyo3="ku10-3" note="13" kijun="sec-95" -->
<!-- /genbun -->
```

- `betten3` … 別添3 の項目 id（通知）。カンマ区切りで複数可
- `hyo3` … 別表第三 の区分 id（告示）／`note` … その中から載せる注番号（`note="4,5,15"` または `note="all"`）
- `kijun` … 特掲診療料 施設基準の id。付けると見出しが「原文を見る（告示・通知・施設基準）」になる
- `summary` … 折りたたみの見出しを自分で決めたいときだけ
- **id は各ページの「原文参照」リンクの `#…` をそのまま使う。** 実行時に見つからない id・注番号は【確認】に出る
- 注の中の点数表（在宅薬学総合体制加算２のイ・ロ等）は字下げした行として取り込まれる
- **置き場所は「摘要欄 → 原文 → 関連する疑義解釈 → 関連する社内Q&A → 関連ページ」の順**。手書きの補足はマーカーの外に置く

**見た目は `assets/source-refs.css` の1枚に集約してある**（2026-08-31）。原文の中身（`.orig`）と最下部の原文参照バー（`.ref-links`）はここだけを直せば全ページに効く。折りたたみそのものの見た目は 2026-09-16 から `assets/fold.css`（上の「折りたたみ」）。**個別ページに同じ定義を書き足さない。** 使うページの `<head>` に `<link rel="stylesheet" href="../assets/source-refs.css" />` を1行入れる。原文参照バーの書き方は下記で統一（インラインstyleで書かない）。

```html
<div class="ref-links">
  <div class="row">
    <span class="lab">原文参照：</span>
    <a href="../改定資料/別添3_調剤報酬点数表に関する事項2026.html#kub-10-3-11">別添３ › 吸入薬指導加算</a>
  </div>
</div>
```

**資料ページの本文幅は 900px に統一**（2026-08-31に860pxの7枚を揃えた）。図解・大きな表のページだけ 980〜1400px の例外。

### 疑義解釈・社内Q&Aは各ページに一覧を自動生成する（2026-07-23）

**正本は1か所**。疑義解釈は `改定資料/疑義解釈まとめ2026.html`、社内Q&Aは `ナレッジ/調剤報酬QA.html` にだけ全文を置き、各加算ページには「要旨＋結論＋リンク」の一覧を **`assets/build-gigi-list.js` で自動生成**する。加算ページに問答を書き写さない（版が上がって番号が振り直されたとき、片方が古くなって食い違うため）。

```bash
node assets/build-gigi-list.js          # 生成して書き込む
node assets/build-gigi-list.js --check  # 差分の確認のみ
```

**正本に追記したら、対応ページにマーカーを置いてスクリプトを実行する。**

- 疑義解釈まとめに追記 → 該当ページに `<!-- gigi-list:sec-○○ -->` … `<!-- /gigi-list -->`
- 調剤報酬QAに追記 → 該当ページに `<!-- qa-list:c-○○ -->` … `<!-- /qa-list -->`
- `sec-○○` / `c-○○` は正本側のカードの id をそのまま書く
- `<head>` に `<link rel="stylesheet" href="../assets/gigi-list.css" />` が必要（見た目は全ページ共通。調整はこの1ファイルで行う）
- **マーカーの間は毎回まるごと上書きされる。** 手書きの補足・自社の解説は終了マーカーの外に置く
- ブロックは `.page` の中に入れる。疑義解釈と社内Q&Aが両方あるページは「関連する疑義解釈 → 関連する社内Q&A」の順に並べる
- 実行するとブロック未設置のカテゴリが一覧表示される。**新しいページを作ったときはこの一覧を見て、繋げるものがないか確認する**
- **NEWチップは疑義解釈まとめ側の `src-chip new` を引き継ぐ**（加算ページ側で個別に付けない）
- **改定資料一覧の「最新の疑義解釈」の1行**（`<!-- gigi-latest -->` 〜 `<!-- /gigi-latest -->`）も同じスクリプトが作る。疑義解釈まとめの「発出一覧」の表の最後の回から作り、押すとその回だけに絞り込んで開く（`#kai-○`）。新しい回を追記したら発出一覧の表に1行足すだけでよい（2026-11-08）
