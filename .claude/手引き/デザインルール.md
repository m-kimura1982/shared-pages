**薄さは目で見て判断しない。測る。** 薄いグレーは「補助テキストらしく」見えてしまうので、目視では気づけない。

```bash
node assets/check-contrast.js                     # 公開ページ全部
node assets/check-contrast.js 加算まとめ/調剤管理料_2026改定.html
node assets/check-contrast.js --ng                # 「要修正」だけ
```

「要修正」は公開前に0件にする。「確認」は矢印・「・」等の記号かもしれないものなので目視で判断する（記号なら薄くてよい）。CSSを読んで判定するため、親から受け継いだ色や後から上書きされる色は分からない。全体点検のときはブラウザで実測する `tools-internal/contrast-scan-browser.js` も通す。`assets/` の共通パーツ（site-header.js / site-search.js / site-recents.js）の色は全ページに効くので、触ったら必ず測り直す。

### 色を使って見やすくする（2026-09-23 に方針を改めた）

**違和感のない色なら、色が増えるデメリットより、情報が見やすくなるメリットを優先する。** 以前は「色は極力抑える」「アンバーは最終手段」としていたが、それは安易に色が増えて見づらくなるのを防ぐための強い言い方だった（本人）。2つを比べる内容や、並列の分類がある内容は、色がないとかえって読みにくい（手本：`ナレッジ/OTC類似薬の一部保険外療養.html`、`加算まとめ/調剤時残薬調整加算.html`）。

色を足すときの条件（OTC類似薬・夜間訪問加算の図解で確かめた付け方）：
- **下の「図解の淡色パレット」から選ぶ。** その場で色を作らない。アンバー（`--amber` 系）もパレットの一員として扱い、2つを対比するときの「気をつける側・制約のある側」に使う
- **1ページの中で、1つの色に1つの意味だけを持たせる**（OTC類似薬は会議スライドに合わせた例外：意味を持たせる色は淡いオレンジ＝特別の料金がかかる だけ。かからない側・保険の分は白かグレー、文字は黒、境目は細線）。表の色も1つの問いにだけ答えさせる
- **色の意味はページの中で決める。サイト全体で「○色＝△」と固定しすぎない**（2026-09-24 本人）。薬歴ページなどは色を多く使っていて、全体で定義すると身動きが取れなくなる。例：新設のバッジは事務サマリ・ダイジェストでは薄緑（変更＝青）、入力画面で解説では青（変更＝藤。同じページで薄緑が「問題ない側」を表しているため）、体系図ではクリーム（廃止が青系のため）
- **塗りを足したら、飾りの色を引く。** 比較表や図を塗り分けたページでは、装飾の box-blue などを減らす
- **色だけに意味を持たせない。** どの色の面にも名前やラベルを書く（モノクロ印刷・色覚特性でも読めるように）
- **並列の分類は濃淡ではなく同じ明るさの淡色で分ける**（濃淡は量の差に読める）
- 文字と地のコントラストは 4.5 以上（`node assets/check-contrast.js` で測る）

変えないもの：**原色の赤（#cc0000 など）は使わない**（見づらく、青との相性も悪い。色を絞っていた頃の「赤は使わない」の本意はここ。配色として合う淡い色なら赤系でもよい＝パレットの薄ピンク）／**黄色は本文のマーカー専用**（飾りに使わない）。

**NG・不可の色はページの中で決める**（2026-10-02 に「グレー＋×で固定」の決まりを外した。本人：その時の色合いに合わせて考えたほうがよい）。決めるときは、同じページで「注意」に使っている色とぶつけない。どの色でも「×」などの記号を添え、色を見なくても分かるようにする。例：選定療養費計算ツールの特管3ロは、可＝薄緑＋✓／不可＝薄ピンク＋×（気をつける側／問題ない側の対）。

### トップとハブの見た目（2026-09-11 刷新）

**3層に分ける。トップは新デザイン、ハブは見出しの帯だけ揃える、資料ページは触らない。** 資料ページは見出しの作りが4種類以上に分かれていて、一律に当てると逆にばらつく。共通ヘッダーとパンくずで「同じサイト」の印は足りている。

- **帯の部品**（淡い青 `#e4eef9` の斜め面に英字ラベル＋題名、右に説明文1文、英字の透かし）。トップの棚の見出しとハブの h1 で共通。**ハブは `assets/hub.css` を link 1行で読むだけ**で、見た目の調整はこの1ファイルで行う。書き方は hub.css の先頭コメントにある。
- **英字はカテゴリ名の大文字**（site-header.js の CATEGORIES の id：KASAN・CHECKLIST・KAITEI・TOOLS・KNOWLEDGE・YAKUREKI・JIMU）。新しく名前を考えない。トップの棚だけは上位の括りなので CHOZAI HOSHU / YAKUREKI。
- **英字の書体 Barlow Condensed は、英字ラベル・透かし・数字にだけ使う。** 日本語の見出しには使わない。使うページは head の Google Fonts の行に `family=Barlow+Condensed:wght@700&` を足す。
- **黄色は本文の黄マーカーと、トップの「現場で使える形」の下線だけ。** 飾り（斜めの帯・見出し横の印など）に使わない。黄は「読ませたい箇所」の印なので、飾りに使うと読者が流すようになり本文のマーカーが効かなくなる。
- **ハブに持ち込まないもの：** ヒーローの斜め面と青線、常時の影、大きな数字、矢印付きの「一覧を見る」。ハブは一覧そのものなので誘導文は要らない。本文幅も900pxのまま（トップだけ1040px）。

### カテゴリ色の実例

並列カテゴリ（区分イ/ロ/ハ/ニ、分類別の箱など）の塗り分けは、上の「色を使って見やすくする」の条件で行う。

- 彩度は抑える。例（残薬調整ページ）：`--grp-zaitaku:#1e5fa8`（在宅＝青）／`--grp-kakari:#6b5ea8`（かかりつけ＝紫）／`--grp-other:#5c6370`（その他＝グレー）
- カテゴリ色は「区別」のための色。強調（青）の意味とは別レイヤーとして扱い、混同させない。アンバーを併用する場合（残薬調整など）も、カテゴリ色／強調／アンバーを互いに混同させない。
- **「NG・不可」の色はページごとに決める**（上の「色を使って見やすくする」）。同じページの「注意」の色と混同させず、「×」印を添える（残薬調整ページのNGケースはグレー＋×）。
- **並列カテゴリを塗り分けるときは、濃淡ではなく同じ明度の淡色にする。** 濃淡は「量の差」に読めるので、順序があるもの（段階・件数）以外に使うと意味を1つ足してしまう。淡色なら文字は濃い同系色にして、コントラスト比4.5以上を確保する。
- **淡いピンク `#fbe4e0`／淡いグリーン `#e3efe0` を同じ図の中に並べると「気をつける側／問題ない側」の意味になる**（`事務/入力画面で解説_2026改定後の入力方法.html` の週1回判定の図）。良し悪しの区別がない分類でこの2色を**対にして**使わない。片方だけを分類色の1つとして使うのは問題ない（薄緑は下のパレットに入れてある）。
- リファレンス実装：`調剤時残薬調整加算.html`（パターン対比・box-amber）／`夜間・休日・深夜訪問加算.html`（時間帯の図解。パレットのクリーム・藤・青＋グレー。隣り合う帯を暖寒で割る）／`ナレッジ/OTC類似薬の一部保険外療養.html`（料金がかかる側だけを淡いオレンジにする。スライドに合わせた例外なので、文字は黒）

### 図解の淡色パレット（ページごとに調色しない）

図解で並列カテゴリを塗り分けるときは、下の5色から選ぶ。**ページごとに色を作ると、同じ意味のものがページごとに違う色になって読者が覚えられない。** 明度をほぼ揃えてあるので、どの2色を隣に置いても「量の差」には読めない。文字色は必ずセットの濃色を使う（背景に黒文字を載せない）。

| 色 | 背景 | 文字 | 文字とのコントラスト |
|---|---|---|---|
| クリーム | `#f3e8d0` | `#7a5718` | 5.4 |
| 藤 | `#e5e0f2` | `#4b3f80` | 7.0 |
| 青 | `#dfe9f6` | `#2a5580` | 6.3 |
| 薄緑 | `#e3efe0` | `#3d6b2e` | 5.3 |
| 薄ピンク | `#fbe4e0` | `#8c3a2e` | 6.3 |
| 淡いオレンジ | `#fce8e2` | `#9a4414` | 5.5 |
| グレー（該当なし用） | `#f2f2f2` | `#444444` | 8.7 |

- **淡いオレンジは2026-09-27に追加。** 社内会議のスライド（青＝構造・番号、オレンジ＝注意すべき結論）と色を揃えるため。OTC類似薬の「特別の料金がかかる」をクリームからこれに替えた。青とオレンジは色覚の違いがあっても見分けやすい。**青に意味を持たせない**（サイトは青ベースで、強調の青と区別がつかない。2026-10-14）。**2026-10-28 に `#fdebdd` から赤寄りの `#fce8e2` に変えた**（黄みがあると灰色の隣で肌色・ベージュに寄り、スライドで見比べて赤寄りのほうが優しく見やすかった。本人）。薄ピンクとはほぼ同じ色になったので、**同じページで淡いオレンジと薄ピンクを並べない**。以前の `#fdebdd` のまま残っているのは薬歴の基本記載ルールの重要度ラベルだけ（OTC類似薬とは別の意味なので変えていない）。
- **3色までに収める。** 4色以上要るなら、たいてい図の分け方のほうを見直したほうがよい。
- **隣り合う帯は暖色と寒色で割る**（クリーム↔藤／クリーム↔青）。藤と青、薄緑と青は明度も色相も近いので隣に置かない。
- **色だけに意味を持たせない。** どの帯にも名前を書く。色は探しやすくするための補助で、モノクロ印刷や色覚特性があっても読めるようにしておく。
- 変数名は用途で付ける（`--tl-yakan-bg` のように「何を表す色か」）。`--green` のような色名は付けない。

### チェックリストの印刷（2026-09-17）

**1枚に収めるために文字を小さくしない。** 詰めて1枚にしたものは、印刷すると小さくて読みにくかった（本人）。収まらなければ2枚にして、2枚目をどのカードから始めるかを `break-before:page` で決める。
- 印刷時の大きさの基準：チェック項目 12.5px／補足・表 11px／カード見出し 15px／いちばん小さい文字でも 10.5px。余白は `@page` で上下 9〜10mm。
- 実例：`チェックリスト/OTC医薬品_区分ごとの販売チェックリスト.html`（2026-09 時点は draft/。A4縦2枚）
- **公開中のチェックリストは直さない**（印刷時の本文 10〜10.5px・最小 8.5〜9.5px のまま）。店舗で印刷済みで、直しても効果が小さいため。**中身を改定するときだけ、ついでにこの基準に合わせる**（改定すれば刷り直すので、そのときなら効果がある）。
- 収まるかは目で見る前に測れる：ブラウザで幅を 710px（A4の印字幅）にし、ページ内の `@media print` の中身を画面用に当てて、カードの高さを足す（A4縦で上下 9mm なら 1054px まで）。最後の確認だけ本人の印刷プレビューで行う。
- **印刷すると1枚目の右上にそのページのQR（公開URL）と印刷日が出る**（2026-10-09。site-header.js の buildPrintQr。QRは `assets/vendor/qrcode.js` で作る）。紙で回覧したあとも最新のページを開けるようにするため。本文の上に約2cm足すので、**チェックリストには自動では出さない**（1枚に収めたものが2枚に押し出される）。チェックリストに付けるときは `<div class="sn-printqr-slot sn-printqr-float"></div>` を `.page-title-wrap` の中に書き、印刷用CSSで `.page-title-wrap { position:relative; }` にする。タイトルの右の余白に重ねて置くので本文を押し下げない（16mm角。タイトルの文字が右端まで届くページでは重なるので測る）。実例：OTC医薬品の販売チェックリスト・自己点検リスト（2026-10-10）。出したくないページは `<meta name="sn-no-print-qr" content="1">`。**店頭に貼る掲示物・様式や、患者に見せる紙を印刷するページには必ず入れる**（チェックリスト以外は何もしないとQRが出る。2026-10-13 に OTC販売の掲示物と様式・選定療養費計算ツールに出ていたのを外した）。**QRだけで1枚目が終わり本文が2枚目から始まるページは `node tools-internal/check-print-qr.js` で見つかる**（Chrome のヘッドレス印刷でPDFにして1枚目の文字を数える。全ページで約3分、ファイル指定も可）。新規ページを作ったときと、印刷用CSS（`@media print`・`break-before` 等）を変えたときに通す。
- **QRに入るのは短いURL `…/shared-pages/q/○○○○○○○`**（2026-10-10）。日本語のファイル名をそのまま入れると約270文字になり、16mm角で1マス0.26mmと細かすぎたため（今は約0.43mm）。7文字はページのパスから計算する（site-header.js と 404.html の `shortId`。**2か所の計算は同じに保つ**）。404.html が page-meta.json の全ページから一致するものを探して転送するので、**ページごとの登録は要らない**。ただし**ページを改名・移動すると、印刷済みのQRは開けなくなる**（404.html の MOVED は旧ファイル名で探すため、短いURLは救えない）。PAGES に未登録のページ（draft/ など）は今までどおり全文のURLが入る。
- **draft/ に置いた未登録のページには、共通ヘッダーが全ページ共通の印刷用CSS（assets/print.css）を足してしまう**（checklist カテゴリだけ除外される仕組みのため）。下書きの印刷を確かめるときは `<meta name="sn-no-print-css" content="1">` を入れる。

### 番号バッジ（順序＝四角／ケース＝◯で形を分ける）
- 順序のある手順（STEP1→2→3 等）＝**青地・白文字の角丸四角バッジ**（26px / radius 7）。塗りつぶしは引き算流儀の例外だが、順序性を示す手順では正当。
- 既存の**ケース番号は黒丸◯**（`.pat-num`）で使用中。ステップは四角にして役割の衝突を避ける。
- 順序のない強調に塗りバッジは使わない。

### 折りたたみ（2026-09-16 に全ページ共通化）

**見た目は `assets/fold.css` の1枚だけで決める。** 事務スタッフが既存の折りたたみに気づいていなかった（左端の小さな「›」が薄いグレーで、帯も白く、見出しに見えていた）ため、公開66ページ・10種類以上あった作りを「枠で囲んだ帯＋右端の『開く／閉じる』」に揃えた。

```html
<!-- カードと同じ並びに置く独立した折りたたみ（原文を見る など） -->
<details class="fold"><summary>題名</summary><div class="fold-body">…</div></details>
<!-- カードの中に置く折りたたみ（解説・詳細・一覧の続き など） -->
<details class="fold-in"><summary>題名</summary><div class="fold-body">…</div></details>
```

- `<head>` で各ページの `<style>` より前に `<link rel="stylesheet" href="../assets/fold.css" />` を読む（書き忘れても site-header.js が補うが、一瞬古い見た目になる）。
- **summary に ▶ や › を書かない。題名に「（折りたたみ）」「タップで開閉」も書かない。** 右端の「開く／閉じる」は fold.css が付ける。
- **個別ページに summary の見た目を書き足さない。** 位置の調整（Q&Aカードの下端に揃える等）だけページ側に書き、詳細度は `details.qa-detail.fold-in > summary` のように fold.css より強くする。
- **読者に必要な情報は畳まない。** 畳むのは原文・長い補足・一覧の続きだけ。迷ったら開いておく（高額療養費の2027年8月の表は `open` にした）。
- `class="fold"` は page-toc.js が目次の見出しとして拾う。カードの中の折りたたみに `fold` を付けない（`fold-in` にする）。
- PCでは開いたまま取っ手を隠す部品（目次・薬歴の「このページの使い方」・他のページの一覧）も `fold-in` を付け、PCだけ枠と取っ手を消している（page-toc.js／yakureki.js／site-header.js の中）。
